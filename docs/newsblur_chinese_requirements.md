# 中文版 NewsBlur 集成需求草案

日期：2026-09-17。基于本地 NewsBlur 提交 `15b2ae60d` 及中文化工作区改动、`LOCALIZATION.md` 和上一轮 hkl-rec 源码评估。

状态：第一批已实现并通过本地验证。中文匹配策略仍仅按现有固定样例覆盖，未做系统性的中文召回评估。

## 目标与架构选择

默认延续此前目标：以 hkl-rec 为主体，选择性迁入中文版 NewsBlur 的阅读、偏好管理和内容组织能力。用户尚未明确选择替换主体或双系统联动，不能据此启动架构迁移。

三种路线：

1. 保留 hkl-rec，按功能迁入（建议）：延续 FastAPI、React、PostgreSQL、MIND/Live 隔离与现有实验；需要重写 NewsBlur 的界面组件和存储适配。
2. 以中文 NewsBlur 为主体：现成阅读器功能较完整，但需要重新对接推荐服务、账户、事件、文章身份和 MIND 实验入口。
3. 两套系统独立运行并联动：保留各自能力，但增加身份映射、状态同步、重复事件和运维复杂度。

以下需求按路线 1 描述；路线 2/3 需要重定集成边界。

## 中文化后确认的变化

- 默认界面语言为 `zh-hans`，保留 `en`；登录态优先读取账号语言，匿名用户使用 Cookie。
- 新增 Web、后端、邮件、客户端、扩展和博客翻译资源；不是只有静态按钮替换。
- AI 请求可传递语言，回答加入语言指令，Ask AI 缓存包含语言，后台任务通过上下文覆盖恢复语言。
- 原始新闻、用户输入、笔记、评论保留原文；语言不自动改变时区。
- `apps/analyzer/models.py`、`apps/clustering/models.py`、`apps/search/models.py` 相对当前 HEAD 无差异。因此不能将这次界面本地化作为中文关键词、分词、聚类、向量效果已经适配的证据。
- `LOCALIZATION.md` 仍列出登录后阅读流程、全主题和原生端运行验收限制。它们是 NewsBlur 本身的待验收项；迁入 hkl-rec 的部分还要单独验收。

## 需求清单与验收标准

| 编号 | 用户需求 | 建议范围 | 验收标准 |
|---|---|---|---|
| R01 | 使用统一的中文产品术语 | 第一批；复用词条含义，适配 React | 菜单、错误、空态、操作反馈一致；占位符正确；原始新闻不被替换 |
| R02 | 收藏和取消收藏，查看收藏文章 | 第一批 | 登录后跨会话保留；重复请求幂等；账户与 MIND/Live 隔离；失效文章显示明确状态 |
| R03 | 标记已读/未读，只看未读 | 第一批 | 可撤销；曝光不直接视为已读；返回列表位置保持；筛选与分页一致 |
| R04 | 关注主题，减少某类内容，屏蔽来源或关键词 | 第一批 | 软偏好与硬屏蔽不同；规则可编辑、暂停和删除；硬屏蔽不被正向得分覆盖；规则命中原因可查看 |
| R05 | 保存搜索并重新查看结果 | 第一批 | 保存查询、语言和分类等条件；与搜索历史区分；进入正确内容空间；无结果有明确提示 |
| R06 | 中文关键词正确匹配 | 第一批，R04 前置条件 | 连续中文句中间的短语能命中；中英混合、大小写、标点有明确规则；不直接照搬英文词首匹配 |
| R07 | 查看同一新闻的其他来源报道 | 第二批，先 Live | 先显示相关报道；经样例验证后才折叠同事件；同主题不同事件不误合并；保留原文与来源 |
| R08 | 获取相关文章和基于兴趣的 Live 推荐 | 第二批，实验入口 | Live 独立索引与评估；内容版本、模型版本可追踪；失败回退当前排序；不混入 MIND 工件 |
| R09 | 用中文获取摘要、问答和简报 | 后续 | 语言跟随请求；明确原文依据；摘要输入不足时不冒充全文；缓存按语言、正文版本、模型和提示词版本隔离 |

R01 默认只要求 hkl-rec 的中文体验完整；中英文切换作为可选扩展，不因 NewsBlur 已有该能力就自动扩大项目范围。

## 产品流程与页面

- 新闻列表：保留推荐/最新与分类浏览；补充收藏、已读状态及偏好操作。
- 文章详情：保留当前结构化正文与原文入口；增加收藏与显式已读操作。相关报道和 AI 功能按阶段接入。
- 我的阅读：聚合收藏文章与保存搜索；阅读历史可后续增加，不与现有列表位置恢复重复。
- 兴趣管理：分别展示“系统学习的兴趣”和“我设置的规则”；重置系统画像不默认删除手动规则和收藏。
- 第一批不增加独立 RSS 管理中心、社交圈、支付会员或移动客户端。

## 建议的具体交互约定

以下均是草案选择，尚未实施：

- 初版已读由用户显式标记；自动已读若后续启用，应依据可见停留等信号，并与手动状态区分。
- 收藏先作为阅读状态，不立即增加画像权重；后续以独立实验验证收藏反馈，避免撤销、重试导致重复加分。
- 屏蔽默认约束信息流；主动搜索可显示“有内容被偏好规则隐藏”，允许用户明确选择包含隐藏结果。
- 修改偏好后开启新一轮信息流，避免旧分页快照与新规则混用；当前页可立即移除被屏蔽项并提示撤销。
- 保存搜索初版按需查询；通知、定时扫描和推送不包含在第一批。
- MIND/Live 状态均以用户、空间、文章身份隔离。语言偏好属于账号层，文章内容语言属于内容层，二者分别保存。

## 技术适配边界

继续使用 PostgreSQL 存储用户文章状态、显式偏好、保存搜索；沿用现有鉴权和事件机制。迁入功能不得要求直接读取 NewsBlur 的生产库或复用其登录 Cookie。

NewsBlur 的中文词库、术语、占位符约定和语言上下文设计可以参考；Django gettext 中间件、MongoEngine 模型、Celery 装饰器和 Backbone 组件需适配目标技术栈。

第一批建议按“收藏/已读 → 中文规则与偏好 → 保存搜索”落地。第二批再建设持久化报道分组、Live 语义索引与个性化实验。既有正文 Worker、搜索、事件链路和阅读位置恢复优先复用。

## 后续范围选择

1. 本批实现按 hkl-rec 为主体；若未来决定以 NewsBlur 为主体或两边双向联动，需要另行设计。
2. 多来源报道聚类、Live 语义召回、每日简报和英文界面尚未实现，属于后续可单独安排的工作。

第一批采用默认中文界面与现有登录态；没有添加与当前范围无关的 NewsBlur 平台迁移或双语 UI。

## 第一批实现记录

已按“hkl-rec 为主体，选择性迁入能力”实现：

- 登录账号拥有按新闻空间隔离的收藏和显式已读状态；重复保存是幂等的，收藏不会自动改变兴趣画像。
- 登录账号可以设置主题、来源、标题关键词规则，并选择优先、减少或强制屏蔽。中文关键词按 NFKC/casefold 子串匹配；来源域名精确匹配，强制屏蔽优先执行。
- 收藏列表保留已失效新闻的收藏记录；支持只看未读收藏文章。
- 保存搜索包含内容空间、语言与分类。打开保存的搜索会遵守规则；被屏蔽结果可由用户明确展开查看。
- 产品信息流通过独立 `/reading/feed` 应用未读与手动规则；底层推荐排序复用当前召回／LightGBM 特征排序并补足候选。研究评估接口 `/feed` 默认路径不读手动偏好。
- 阅读分页快照绑定用户、空间、过滤条件及阅读状态/规则版本；偏好变化后刷新快照，旧游标返回 409。

本地验证记录：6 项前端阅读工具交互测试通过；完整前端测试 168 项通过，生产构建通过；6 项阅读 API PostgreSQL 集成测试和 25 项迁移/分页回归共 31 项通过；相关 Ruff 检查与隔离模块 Mypy 检查通过。

限制：MIND 个人信息流最多对 2,000 个合规候选生成一份阅读快照，以限制单次排序规模；新信息或状态变化后重新生成快照。当前删除文章状态保留收藏显示，允许打开不可用提示；没有新增永久全文复制。完整后端测试曾发现迁移头和表清单断言未跟进新迁移，相关断言已更新，并且它们所在的 31 项定向测试通过；完整后端测试尚未在这些断言更新后重跑。
