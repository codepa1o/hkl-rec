# 顶部账号菜单设计

## 目标

将右上角重复出现的登录账号、退出按钮和推荐画像切换器合并为一个紧凑账号入口。顶部只显示一次登录用户的头像和姓名；邮箱、推荐画像切换和退出登录均放入下拉菜单。

## 当前问题

- 登录账号名称和当前推荐画像名称并列显示，同名时形成明显重复。
- 退出登录是独立图标，含义依赖悬浮提示，入口不够自然。
- 推荐画像与登录账号视觉权重相同，用户难以判断两者的层级关系。

## 已确认方案

采用“紧凑账号胶囊”：保留独立主题切换按钮，其右侧仅放置一个账号按钮。按钮由 30px 头像、登录姓名和下拉箭头组成，高度约 42px，与现有顶部控件对齐。

展开后的菜单宽约 286px，包含三层信息：

1. 账号信息：头像、登录姓名和邮箱。
2. 推荐画像：账号自身显示为“我的画像”，其他画像使用现有中文本地化名称；当前项显示柔和紫色背景和“当前”标记。
3. 账号操作：退出登录位于底部独立区域，使用低饱和危险色。

## 交互

- 点击账号胶囊切换菜单开关。
- 点击菜单外部、再次点击胶囊或按 `Escape` 关闭菜单。
- 选择推荐画像后调用现有 `selectPersona(userId)`，随即关闭菜单。
- 点击退出登录调用现有 `logout()`；请求期间禁用按钮，失败时在菜单底部显示中文错误信息。
- 使用 `aria-expanded`、`aria-haspopup`、`role="menu"` 和 `role="menuitemradio"` 表达菜单及选中状态，键盘用户可通过 Tab 访问各项。

## 响应式行为

- 桌面端显示头像、姓名和下拉箭头。
- 560px 以下隐藏姓名和箭头，只保留头像，但菜单结构保持不变并右对齐。
- 姓名过长时单行省略，不能挤压主题按钮或搜索框。

## 组件边界

- 新增 `AccountMenu`，统一读取 `useAuth()` 与 `usePersona()`，独立处理菜单状态、画像切换和退出登录。
- `TopNav` 只负责布局、主题切换和渲染 `AccountMenu`。
- 删除不再使用的 `PersonaSwitcher`，避免两套身份入口并存。
- 样式集中放入现有 `global.css`，沿用当前色彩变量、圆角和阴影体系。

## 验收标准

- 顶部登录姓名只出现一次，不再显示独立退出按钮和独立画像切换器。
- 展开菜单能看到姓名、邮箱、画像列表、当前画像状态和退出登录。
- 画像切换、外部点击关闭、Escape 关闭及退出登录均可用。
- 浅色、深色和窄屏布局均保持清晰，不影响搜索区。
- 新增组件测试并通过前端全量测试与生产构建。
