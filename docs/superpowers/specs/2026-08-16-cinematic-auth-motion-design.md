# 登录页电影式场景动效设计

日期：2026-08-16
状态：已获用户确认
适用范围：`product-frontend` 登录与注册页面

## 1. 目标

在保留现有深色编辑感、紫色品牌色和登录/注册功能的基础上，将认证页升级为“强视觉沉浸”的电影式场景。动效必须服务于页面状态：首屏进入、表单聚焦、登录/注册切换、请求等待、错误和成功，而不是只播放无意义的循环背景。

成功标准：

- 用户首次看到页面时，能感知清晰的片头式层次，但表单在 700ms 内可稳定操作。
- 登录与注册的切换由全屏斜切幕布完成，并在遮挡阶段交换内容，不出现闪烁或布局跳动。
- 请求中、错误和成功状态具有可辨识反馈，且不改变现有认证 API 与路由语义。
- 桌面端与移动端均可用；键盘操作、屏幕阅读器和减少动态偏好不受损。
- 动效只使用合成友好的 `transform`、`opacity`、`clip-path` 和有限的 `filter`，不持续触发页面布局计算。

## 2. 调研结论

- [Motion](https://github.com/motiondivision/motion) 提供 React 动画、手势、布局过渡和 presence 管理，采用 MIT 许可，适合状态驱动的场景编排。
- [React Bits](https://github.com/DavidHDev/react-bits) 展示了丰富的背景与文字动效语言，但采用 MIT + Commons Clause。本项目只借鉴视觉模式，不复制其组件。
- [OGL](https://github.com/oframe/ogl) 适合 WebGL 粒子或着色器背景，但方案 C 不需要引入 WebGL 的运行成本与维护复杂度。
- [NutriGo 的认证页](https://github.com/tung-programming/nutrigo/blob/main/app/auth/login/page.tsx) 将鼠标、输入聚焦和认证结果绑定到视觉反馈，证明了“认证状态驱动画面”的可行性；本项目避免把所有视觉和业务逻辑放进单一页面组件。

最终选择方案 C“电影式场景切换”，不采用角色、粒子场或 WebGL。

## 3. 视觉结构

### 3.1 桌面端

页面仍由故事区和表单区构成，但紫色斜切幕布跨越两区，成为统一的场景元素：

- 故事区约占 58%，承载品牌、眉题、大标题和说明文字。
- 表单区约占 42%，使用近黑色平面承载登录或注册表单。
- 前景加入低透明度噪点纹理，增强电影画面质感；纹理不响应指针，也不阻挡交互。
- 主幕布使用品牌紫，后方设置一层低透明度浅紫幕布，形成景深。

### 3.2 移动端

宽度小于 760px 时切换为上下布局：

- 故事区缩短，只保留品牌、眉题和主标题。
- 表单区位于下方，确保输入框和提交按钮无需横向滚动。
- 幕布仍执行横向扫场，但斜率和覆盖宽度降低，避免遮挡时间过长。
- 页面允许纵向滚动，兼容移动键盘弹出后的可视区域变化。

## 4. 动效时间线

### 4.1 首屏进入

总时长控制在 700ms 内：

1. `0–180ms`：紫色斜切幕布从画外进入。
2. `140–520ms`：故事标题逐行从下方 24px 淡入，模糊从 8px 降为 0。
3. `240–620ms`：表单从右侧 24px 淡入。
4. `620–700ms`：所有元素进入稳定状态，停止首屏动画。

页面加载期间不锁定输入；动效只是视觉入场。

### 4.2 登录/注册切换

切换总时长约 700ms：

1. 用户点击切换操作后，立即清除旧错误并暂时锁定重复切换。
2. 幕布在 330ms 内横扫覆盖画面，同时旧文案和表单淡出。
3. 画面被完全遮挡时切换 `login` / `register` 模式及文案。
4. 幕布在随后 370ms 离场，新表单和标题错峰淡入。
5. 动画完成后恢复切换按钮，并将焦点放到新模式的首个输入框：登录为邮箱，注册为显示名称。

### 4.3 输入聚焦

- 输入框底线在 180ms 内变为品牌紫。
- 表单整体不位移，避免输入时产生干扰。
- 密码可见性按钮保留现有功能，只增加颜色和轻微透明度反馈。

### 4.4 请求等待

- 提交按钮保持原尺寸，文案变为“正在登录…”或“正在创建…”。
- 按钮内出现单向流光；表单控件与模式切换暂时禁用。
- 幕布轻微向画面中心收紧，但不循环加速，不制造虚假的进度预期。

### 4.5 错误

- 表单容器执行一次 240ms、最大位移 4px 的水平反馈。
- 错误提示沿用 `role="alert"`，以左侧危险色线条和淡入显示。
- 背景与幕布不变色、不闪烁，避免把错误放大成全屏警报。
- 用户修改任一输入后，保留后端错误，直到下一次提交或切换模式；不擅自隐藏服务端反馈。

### 4.6 成功与跳转

- 本次登录或注册请求成功后，幕布在 680ms 内闭合为全屏紫色场景。
- 中央显示“阅读世界正在展开”，随后导航到原受保护路径或首页。
- 如果进入认证路由时已经存在有效用户，会立即导航，不播放成功动画，避免已登录用户看到认证页闪屏。
- 成功转场最长只延迟本次交互 680ms；减少动态模式下不延迟导航。

## 5. 组件与状态边界

### 5.1 `AuthPage`

继续负责：

- 登录/注册模式和输入值。
- 调用 `AuthContext` 的 `login`、`register`、`clearError`。
- 解析登录前目标路径。
- 判断当前认证是否来自本次提交，并控制成功导航时机。

不再直接承载复杂的幕布 DOM。

### 5.2 `AuthCinematicStage`

新增纯展示组件，负责：

- 品牌与故事文案。
- 主幕布、后幕布、噪点层和场景布局。
- 首屏、模式切换、请求、错误和成功的视觉变体。
- 接收 `mode`、`phase` 和减少动态状态，不调用认证 API。

建议接口：

```ts
type AuthMode = "login" | "register";
type AuthPhase = "entering" | "idle" | "switching" | "submitting" | "error" | "success";

interface AuthCinematicStageProps {
  mode: AuthMode;
  phase: AuthPhase;
  reducedMotion: boolean;
  children: React.ReactNode;
}
```

### 5.3 状态流

```text
entering → idle
idle → switching → idle
idle → submitting → error → idle
idle → submitting → success → navigate
```

- `switching` 期间只锁定模式切换，不阻止浏览器焦点离开页面。
- `submitting` 由现有 `loading` 状态和本地提交状态共同决定。
- `success` 只允许由当前页面发起的成功请求触发。
- 组件卸载时清除切换与导航计时器。

## 6. 技术方案

- 新增 `motion` 依赖，使用 `motion/react` 和 `AnimatePresence` 管理文案、表单与幕布变体。
- 使用 CSS 自定义属性维持当前主题变量，不引入 Tailwind、GSAP、Canvas 或 WebGL。
- 噪点纹理使用内联 SVG data URL 或纯 CSS，避免新增网络资源。
- 通过 Motion 的减少动态支持或 `matchMedia("(prefers-reduced-motion: reduce)")` 提供降级。
- 登录与注册的业务请求、Cookie、`AuthContext` 和后端接口保持不变。

## 7. 无障碍与降级

- DOM 顺序保持品牌/说明在前、表单在后，视觉幕布使用 `aria-hidden="true"`。
- 切换按钮、密码可见性、错误提示和输入标签保留明确的可访问名称。
- `prefers-reduced-motion: reduce` 时：取消首屏位移、全屏扫场、模糊和错误横移；模式内容以 100ms 以内的透明度变化替代；成功后立即导航。
- 所有操作支持键盘；切换模式后进行明确的焦点迁移。
- 动效层设置 `pointer-events: none`，不覆盖输入和按钮。

## 8. 性能约束

- 同时运行的持续动画不超过一项，稳定状态下不运行 `requestAnimationFrame`。
- 主要动画限定为 `transform` 与 `opacity`；`filter` 只用于短暂入场，移动端可关闭。
- 幕布层数量固定为两层，噪点层一层，不生成动态粒子。
- 不监听全局鼠标移动。
- 构建后检查新增依赖体积，并在真实浏览器验证无明显卡顿或布局偏移。

## 9. 错误处理

- 认证请求异常继续由 `AuthContext` 产生统一错误文案。
- 页面捕获异常只用于结束提交阶段，不覆盖上下文错误。
- 快速重复点击模式切换、提交或密码可见性时不得产生并发计时器或状态错位。
- 组件卸载后不得继续执行状态更新或延迟导航。

## 10. 测试策略

### 10.1 组件测试

- 默认渲染登录文案和字段。
- 切换注册后，在遮挡中交换内容，完成后聚焦显示名称。
- 提交期间禁用表单并显示正确等待文案。
- 请求失败后显示 `role="alert"`，并恢复可提交状态。
- 本次请求成功时先进入成功阶段，再导航到原路径。
- 页面初始已有用户时立即导航。
- 减少动态模式下跳过延迟与位移动画。
- 快速重复切换不会产生错误模式或多次提交。

### 10.2 构建与浏览器验证

- 运行 Vitest 全部前端测试。
- 运行 TypeScript 与 Vite 生产构建。
- 在桌面宽屏、窄屏和移动尺寸验证布局。
- 使用键盘完成登录/注册切换、输入、密码可见性和提交。
- 模拟减少动态偏好并验证降级。

## 11. 验收条件

- 页面呈现已确认的方案 C 斜切幕布与分层入场。
- 登录/注册功能、错误显示、密码可见性和原路径返回行为没有回归。
- 登录/注册切换和成功导航具有规格描述的电影式转场。
- 移动端不横向溢出，虚拟键盘弹出后表单仍可操作。
- 减少动态偏好下没有大范围移动或延迟导航。
- 所有新增测试、既有前端测试和生产构建通过。

## 12. 非目标

- 不修改后端认证协议或账户模型。
- 不增加第三方登录、忘记密码或记住登录功能。
- 不引入 3D、WebGL、角色动画、粒子系统或声音。
- 不重构认证页以外的全局视觉系统。
