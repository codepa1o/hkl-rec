# 独立兴趣画像页设计

## 目标

将左侧“兴趣画像”从当前页锚点升级为可直接访问的 `/profile` 页面。页面只展示登录用户的正式 Profile V2 画像，复用现有解释、错误处理和一键重置能力，不新增画像编辑或语义向量功能。

## 方案选择

采用独立主内容页方案：保留顶部导航和左侧菜单，在 `/profile` 隐藏右侧栏，让画像占据主内容区。

未采用以下方案：

- 在三栏布局中同时显示中央画像与右侧画像，因为会产生重复内容和重复请求。
- 使用弹窗或抽屉，因为它没有稳定 URL，也不符合“进入独立页面”的用户预期。

## 页面与路由

- 左侧入口改为 `NavLink to="/profile"`，并使用现有激活态样式。
- `App` 注册 `/profile` 路由并渲染 `ProfilePage`。
- 产品壳根据当前路径添加画像页布局状态；该状态保留左侧栏，隐藏 `RightRail`，主内容区占据剩余宽度。
- 其他路由的三栏布局保持不变。

## 组件边界

### `ProfilePage`

负责页面级标题、说明和主内容布局。它从 `PersonaContext` 读取 `refreshTick` 与 `bumpProfile`，将二者传给现有画像组件，但不读取演示 persona 身份来决定画像用户。

### `ProfilePanel`

继续负责调用正式 `GET /profile`、展示短期兴趣、长期兴趣、减少推荐、置信度、证据解释和重置操作。新增显式展示模式，用于在右侧栏和独立页面之间切换样式；两种模式共享同一数据与交互逻辑。

### `RightRail`

非画像路由保持现有行为。画像路由由产品壳隐藏该区域，因此不会重复加载正式画像。

## 数据流

1. 用户点击左侧“兴趣画像”。
2. React Router 导航到 `/profile` 并高亮入口。
3. `ProfilePage` 挂载 `ProfilePanel`。
4. `ProfilePanel` 使用登录 Cookie 请求 `GET /profile`。
5. 重置成功后调用 `bumpProfile()`，使返回信息流后能够按新画像刷新。

正式画像始终由后端登录会话确定用户；本页面不调用 `/debug/profile?user_id=...`。

## 视觉与响应式

- 沿用项目当前深色、紫色强调和编辑式留白，不引入新的视觉体系。
- 页面标题与说明位于画像内容上方，画像主体在宽屏下获得更宽的阅读区域。
- 主题分组在宽屏下使用多列布局，在窄屏下回落为单列。
- 重置操作仍位于画像内容末尾，并保留二次确认。

## 错误处理

- 加载、空画像、请求失败和重新加载沿用 `ProfilePanel` 的现有状态。
- `/profile` 返回 401 时继续触发现有全局未登录处理。
- 画像页不增加额外重试策略或后端降级逻辑。

## 测试与验收

- 左侧入口的目标地址为 `/profile`，且在该路由处于激活状态。
- `/profile` 能渲染独立页面标题和正式画像内容。
- `/profile` 布局不渲染右侧画像栏；其他页面仍保留右侧栏。
- 现有画像加载、错误、空状态和重置测试继续通过。
- 前端全部 Vitest 测试通过，TypeScript 与 Vite 生产构建通过。
- 本地浏览器中点击入口后 URL 变为 `/profile`，并能看到画像内容。

## 非目标

- 不支持逐主题手动编辑。
- 不改变 Profile V2 API 或数据库结构。
- 不改变推荐默认实验分组。
- 不重构无关导航、信息流或右侧栏功能。
